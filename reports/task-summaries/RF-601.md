## 完成内容

CodeMirror 与纯语义引擎之间的转换层现在是独立包 `@fishmark/codemirror-adapter`：

- `transaction-adapter.ts`：每个 view 的 `DocumentStructureCache` state field（单范围走增量缓存、多范围/不可证明时全量重解析，revision 每次变更严格 +1）；`prepareCommand`/`preparePlan` 在派发前给出 `applied | unchanged | unhandled | frozen | stale` 判定；`recordEditorDispatch` 用「事务将产生的 cache revision + 文档文本」双重校验后，把 `baseText/resultingText/changes` 帧交给既有队列；组合输入期间拒绝结构决策。
- `selection-mapper.ts`：`SelectionMapper` 按 (snapshot, selection) 复用上下文，光标移动不重建文档派生快照；`checkPlanRevision` 区分 `stale`（revision 不匹配）与 `foreign-session`（generation 不匹配）。
- `composition-controller.ts`：纯状态 IME 控制，组合期间冻结几何刷新，结束按最终文本请求恰好一次重算并给出显式原因。
- `candidate-performance.ts`：候选路径性能探针，直接测量 adapter 使用的同一组缓存操作。
- history 分组：普通输入保持 CodeMirror 原生 typing 组（连续键入合并为一次撤销），结构补全用 `isolateHistory` 独立成步，导航不产生 history 事件。

关键实现修正（均由测试证伪后修复，非事后解释）：

1. plan 的「来源 session」最初与当前 session 比较，是同义反复，无法发现 rebind；改为 `EditorPlanSessions` 记录生成 plan 的 generation，跨 session 判定 `foreign-session`。
2. `readLocalRevision` 最初返回绑定时的快照，document 编辑后不前进；改为读取实时 cache revision（session 快照只是报告，不是版本 owner）。
3. `recordEditorDispatch` 最初拿帧的 baseText 与派发**之后**的文档比较，导致所有帧被判 stale；改为比较预期 revision 与 resultingText。
4. 帧最初取自 cache.source，而 cache 可能仍带 CodeMirror 归一化（CRLF→LF）之前的文本；改为读取实时文档。
5. 所有命令最初都写成 `input.<commandId>`，实测把连续键入拆成多次撤销；`insert-text` 特判回 CodeMirror 原生 `input.type`。

边界与删除：`packages/editor-core/src/commands/editor-model-bridge.{ts,test.ts}` 与其 3 条 guard 例外被删除（guard 禁止 adapter 之外的包 import `@codemirror/*`，保留即两份实现）。guard 中 `codemirror-adapter` 由 `planned` 激活为 `active` 并绑定 `boundary.codemirror-adapter`；新增包别名到 `tsconfig.base/renderer/vitest` 与 `vite.config.ts`/`vitest.config.ts`。

**没有第二套队列**：adapter 只依赖窄端口 `EditorChangeFramePort.admitFrame`，真实集成由 `src/renderer/editor/codemirror-adapter-queue-integration.test.ts` 用真实 `WorkspaceEditClient` 验证。三种版本语义保持分离且都不由 adapter 拥有：`localRevision`（自身缓存）、`acknowledgedRevision`（main 已确认）、`observedRevision`（投影观测）。
