# RF-703 — Outline and metrics cutover

Status: **COMPLETE** (2026-09-22)

## Outcome

- `EditorDerivedSnapshot` is the single document-revision owner for root outline headings and document metrics.
- Renderer `outline.ts` and `document-metrics.ts` are projection-only consumers; they do not parse Markdown source.
- Outline identity is the canonical Markdown node id shared with active-heading state.
- Metrics consume canonical tree/inline/table metadata and physical-line geometry; structure markers are not re-scanned in renderer.
- React refreshes derived UI from snapshot identity/revision. The existing 120ms presentation debounce remains, but it no longer schedules a second Markdown parse.
- Raw-content derived scheduling was removed from the editor workflow.

## Performance evidence

The initial RF-703 probe incorrectly hard-coded expected consumer counters. Owner review rejected that as self-referential evidence.

The accepted probe now:

- uses one `MarkdownParseInstrumentation` tracker;
- records exactly one shared snapshot build separately from underlying parse events;
- measures Outline and Metrics with before/after parse-event deltas;
- requires both consumer intervals to add zero full-document and zero inline parse events;
- attributes no cache hit to the consumers themselves because snapshot/cache reuse is owned upstream.

The frozen performance baseline was re-recorded only for the two operations whose semantics legitimately changed:

- Outline: independent full parse removed; unavailable capability reason cleared.
- Metrics: independent full parse and legacy `parseMarkdownDocument` entry removed; unavailable capability reason cleared.

No unrelated baseline operation was modified.
