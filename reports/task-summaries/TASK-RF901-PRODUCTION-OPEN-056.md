## 协议与结果

使用真实生产 main、sandbox preload 和 Vite renderer；每种文档启动一个隔离新进程、新 profile，随后通过真实 File > Open 菜单打开两个内容相同、路径不同的文件。文件选择器仅替换为隔离夹具路径，授权、读取和编辑流程使用产品实现。计时从生产 main require 前或暖打开菜单回调前开始，直到目标标签与非空可编辑 DOM 出现，再等待 fonts.ready 和两次 requestAnimationFrame。DOM 检查间隔 20 ms。完整内容、追加、撤销和磁盘原文检查均在计时结束后进行。

这里的“冷”表示新应用进程和新 profile，不是清空操作系统磁盘缓存，也不包括进程创建之前的时间；两次 RAF 不等于显示器实际呈现。关闭 Playwright tracing，不开启 CPU profiler。窗口 1280×900，DPR 1，实际内容区域 1264×835，浅色主题、效果关闭。每批每个尺寸只有一个新进程和两个暖打开样本，不形成 p95 或稳定提速比例。

单位 ms，均为 fonts + 两次 RAF 后的 readyMs；原始报告另含 DOM 时刻。

## 实现

`collectMicromarkEventViews` 增加仅供结构扫描调用的模式，禁用强调、链接、行内代码等行内事件；默认调用行为不变。引用定义扫描复用同一禁用列表，保留原有 CommonMark 定义语义，不额外启用 math。块级结构、定义、转义和实体处理保持，完整行内 AST 仍由 `parseInlineAst` 生成。没有改扫描计数、编辑历史、授权机制或性能阈值。

新增独立 `playwright.open-performance.config.mjs`、产品测试入口辅助模块和 probe。正常产品 E2E 不开启该测量；性能报告单独记录 `budgetVerdict`，协议测试通过不能代替预算通过。可复跑命令：

```powershell
npm run build
$env:FISHMARK_E2E_RUN_ID = 'm9-open-新的唯一批次名'
node node_modules/@playwright/test/cli.js test --config playwright.open-performance.config.mjs
```

仅诊断时可设置 `FISHMARK_E2E_OPEN_PROFILE` 为不存在的绝对文件路径；该运行有 profiler 开销，不能与正式样本混合。5k 诊断中，约 1105 ms CPU 采样区间含约 578 ms idle，说明继续压缩解析不足以覆盖全部启动耗时。补测页面导航约 102 ms；尚未定位分散等待的具体责任方，下一步应记录主进程初始化、模块加载及 workspace IPC 的分段时序。未凭此猜测修改启动顺序。
