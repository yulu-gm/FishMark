# RF-203 Renderer Workspace Client and Pending Edit Queue

Task: `RF-203`

结果：`PASS` — independent spec review, quality review, architecture review, and formal task acceptance.

## 完成内容

- Added a pure, runtime-neutral pending edit queue (`src/renderer/application/pending-edit-queue.ts`) that owns, per tab, one atomic transport baseline `{ acknowledgedText, acknowledgedTextRevision }`, separate UI-only observed metadata, optimistic local text, ordered unsent batches, at most one in-flight batch, the next client sequence, and a lifecycle generation. It implements hydrate/enqueue/begin-send/admit-result/observe-projection/rebase/retire/retry/recovery transitions and a conservative three-way rebase for provably non-overlapping local edits.
- Added the `WorkspaceEditClient` (`src/renderer/application/workspace-edit-client.ts`) with one random client identity per client lifetime (never reused across renderer reloads), per-tab sequence high-watermarks, composition-aware and plain edit barriers, two-phase conflict preparation/commit with claim tokens, typed discard-to-recovery retention, ABA epoch fences, exactly-once dispose/cancel semantics, and all-tab failure cleanup.
- Extended the CodeMirror adapter (`src/renderer/code-editor.ts`) with a single RAF frame bucket composing same-frame `ChangeSet`s into repository-owned `DocumentTextChange[]` frames, a composition-aware seal (`sealForBarrier`) that waits for the final post-`compositionend` checkpoint, an `internalDocumentTransaction` annotation the observer ignores, and identity-fenced `applyRemoteDocumentPatch` / `restoreCanonicalDocument` remote transactions.
- Hard-switched the production editor path to the revisioned transport; the legacy full-draft channel remains compiled only as explicit RF-204 deletion debt and cannot run for the same edit as the new client. `WorkspaceRendererApplication` enters incremental mode at pending frame admission; save/autosave/close/detach/window-close/export use real revisioned barriers; `sealForBarrier` returns an immutable cutoff snapshot so a tail typed while a barrier waits can never be exported outside the checkpoint.
- Conflict/recovery: on `revision-conflict` the queue stops pumping, retains every local change, and either rebases conservatively or freezes the queue and retains the exact local text as a recovery payload; recovery tabs are created with a private IPC path, hydrated at revision 0 with exact incremental payloads, and the old queue retires only after the recovery tab acknowledges that exact text. A `recovering` editor transition freezes the source editor before recovery creation.
- Quality-review Critical C1 closure: non-conflict recovery sources (adapter discard, invalid frame, missing sequence) now auto-materialize a recovery tab through the same coordinator as the conflict path, so `getRecoveryPendingOutcome` cannot permanently block window close; duplicate discards do not double-create.
- Architecture guard updates: the remote-patch no-history contract (internal-origin annotation pairing, exactly one occurrence) and a runtime-neutrality guard for `src/renderer/application/*` were added to `src/main/editor-foundation-architecture.test.ts`; the real-repository manifest test gained a 30 s timeout.
