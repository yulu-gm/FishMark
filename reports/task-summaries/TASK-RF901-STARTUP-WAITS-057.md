# RF-901：定位启动等待并减少渲染挂载延迟（2026-10-28）

本批基于 `b0ab235`。冷打开仍有优化空间，已确认并减少渲染端串行懒加载的等待。同机交替对照中，5k 冷打开从 1304–1306 ms 降至 862–975 ms，20k 从 1930–1987 ms 降至 1578–1715 ms。仍超过 500 / 1500 ms 预算，RF-901 未验收，M9 保持 0/3。

## 分段定位

新增仅由隔离产品测试入口启用的 `FISHMARK_E2E_OPEN_TIMELINE`。主进程使用同一个单调时钟，记录生产 main 加载结束、app ready、窗口创建、DOM ready、CDP 模块解析事件和真实 IPC handler 起止。记录先放内存，在 editor-ready 后落盘，不修改 IPC 参数、返回值、文件授权或产品启动代码。CDP 事件是主进程接收时刻，可能被批量送达，不能当成每个模块的精确 CPU 时间。

5k 诊断的代表时刻（ms，自生产 main require 前起算）：

| 阶段 | 修改前 | 最终候选 |
| --- | ---: | ---: |
| main require 完成 | 未单独记录 | 40 |
| app ready | 70 | 73 |
| 窗口创建 | 110 | 117 |
| DOM ready | 246 | 248 |
| 应用模块解析事件 | 257 | 256 |
| 首批工作区 IPC | 600 | 265 |
| 打开文件 handler 完成 | 622 | 282 |
| editor-ready | 1343 | 770 |

工作区快照 handler 小于 1 ms，打开文件 handler 约 11–13 ms，主题包目录约 6 ms；app ready 到窗口创建约 40–45 ms。它们不是本批最长的等待。修改前应用模块已解析，但约 340 ms 后才触发工作区初始化 effect。当前本地 React 19.2.5 生产实现包含 `globalMostRecentFallbackTime + 300` 的 Suspense 重试节流；移除必经的外壳 Suspense 后，这一阶段明显提前。后续编辑器懒加载也经过一次等待，因此一并调整。

诊断证据为 `.artifacts/startup-timeline-01.json` 与 `startup-timeline-04.json`。其中 02/03 是中间实验，包含直接合并编辑器模块的方案，不能拿最快的 722 ms 作为最终实现的正式结果。CPU profiler 与 timeline 开关互斥，诊断结果不混入以下无诊断测量。

## 最终实现

- `main.tsx` 保留应用动态分包，在应用模块完成后才创建并挂载 React 根组件。`App.tsx` 直接引用必经编辑器外壳，避免先提交空 fallback 再重试。
- 编辑视图继续按需加载，不进入空工作区静态依赖。`DeferredCodeEditorView` 在模块就绪后通过普通状态更新呈现，缓存模块供后续挂载复用；加载期间卸载不会更新旧实例，加载失败仍交给应用错误边界，ref 和文档协议参数原样转发。
- 可选主题、标题栏、快捷键提示、语言包、数学、图表和导出继续保留原按需边界。没有改主进程初始化顺序、恢复协议、授权、文件读取、解析器或预算。

直接静态合并全部编辑器模块的实验虽然更快，却使首屏 gzip 超标，已放弃。最终 `perf:baseline` 原约束通过，首屏静态依赖 gzip 为 104134 bytes，低于 260000 bytes 限制。源码分包检查跟随动态导入移动到专用组件，继续检查 shell 无静态编辑器引用、组件仅 type import 加动态 import；未放宽预算或删除检查。

## 无诊断生产复测

使用报告056协议，按“修改前 → 候选 → 修改前 → 候选”交替重新构建 renderer。两种文档各一个新进程、新 profile、两个不同路径的暖打开；没有清空操作系统缓存，不含进程创建前时间，也不代表 compositor 或 p95。测量期间不运行其他测试。每次计时后均验证完整内容、追加、撤销和磁盘原文不变，最后核验隔离退出和清理。

| b0ab235 第1轮 | 1304 | 272 / 271 | 1930 | 1102 / 939 |
| 候选第1轮 | 975 | 395 / 286 | 1578 | 1124 / 996 |
| b0ab235 第2轮 | 1306 | 292 / 281 | 1987 | 961 / 934 |

两组对应冷打开均缩短，观察到约 270–440 ms 的改善。所有暖打开均低于相应预算，但候选暖样本也出现上升，不能宣称暖打开没有变化；样本不足以区分运行波动与稳定差异。两种尺寸的最终预算判断均为 FAIL。

证据在 `.artifacts/e2e/m9-startup-{baseline,candidate}-{1,2}/`，每个报告包含生产入口哈希、夹具哈希、隔离身份及预算判定。执行脚本 `.artifacts/startup-paired.mjs` 用原始字节保存和恢复当前三个源码文件，构建前后没有混用源码版本；最终恢复候选并重新执行完整 build。用户原有版本号、锁文件及发布说明修改保留。

剩余冷打开耗时主要落在模块就绪后的编辑器创建、首次解析与布局，以及字体和两帧等待。主进程约百毫秒即可创建窗口，工作区 IPC 为毫秒量级；下一步优先继续分解编辑器创建的 CPU 与布局成本，而不是改动数据恢复或授权时序。当前没有证据支持通过延迟恢复或绕过授权进一步提速。
