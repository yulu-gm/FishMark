# RF-101 Workspace Domain Intake

Date: 2026-07-16
Task: RF-101
Status: IN_PROGRESS — design approved, implementation plan pending execution

## Goal

Extract all canonical window, tab, document-session, revision, dirty, ordering, move, detach, close, and projection rules from `src/main/workspace-service.ts` into the runtime-neutral `@fishmark/workspace-domain` package. Cut main callers over to the package public entry and delete the old service without leaving a facade or dual implementation.

The validated design is `docs/superpowers/specs/2026-07-16-rf-101-workspace-domain-design.md`.

## In scope

- Create a real local runtime package for `@fishmark/workspace-domain`.
- Add `DocumentRevision`, `DiskVersion`, immutable `TextBuffer`, `DocumentSession`, `WorkspaceState`, projections, and public index.
- Use revision equality as the only dirty calculation.
- Preserve restore-to-saved clean behavior through an exact saved-text checkpoint.
- Capture revision/text at save start so asynchronous completion cannot overwrite or incorrectly clean newer edits.
- Serialize Save, Save As, reload, and close per tab through one main-owned application IO coordinator; hold native window-close tab leases through unregister.
- Move all pure workspace rules from the old service into the package.
- Preserve current shared IPC DTO shapes and renderer/preload behavior.
- Activate the workspace-domain architecture manifest entry and boundary rule.
- Cut over `main.ts`, `workspace-application.ts`, and `workspace-close-coordinator.ts`.
- Delete `src/main/workspace-service.ts`, replace its tests, and prove zero old imports/exports remain.
- Update package and RF documentation.

## Out of scope

- RF-102 application ports/use-case extraction.
- RF-201 CodeMirror persistent `Text` adapter.
- RF-202–RF-204 revisioned IPC and full-draft deletion.
- Watcher, recent files, recovery, safe-save, and external-conflict redesign.
- Renderer store/controller or preload contract restructuring.
- Markdown parser, cache, nested structure, editor command, IME, cursor, or visual behavior changes.
- General MVP backlog/progress edits.

## Required invariants

1. Main owns the only writable workspace/session state.
2. Markdown text remains the only document truth.
3. Domain has no Electron, React, DOM, CodeMirror, filesystem, watcher, dialog, or IPC dependency.
4. Domain buffers and returned projections cannot be mutated back into canonical state.
5. A text change increments revision once; identical content does not increment.
6. `isDirty` is never stored or caller-controlled.
7. Undo/manual restoration to durable content becomes clean immediately.
8. Save completion is bound to the captured revision and never overwrites newer text.
9. Same-tab IO operations are FIFO-exclusive without a global mutex or delaying `updateDraft`; unrelated tabs remain independent.
10. Confirmed native window discard holds every affected tab lease until the window is unregistered, so queued autosave cannot write afterward.
11. Current IPC DTOs and channel names remain unchanged.
12. RF-101 cannot finish with the old service, a compatibility wrapper, duplicate types, or dead exports.

## Risks

- TypeScript aliases do not rewrite Electron runtime imports; package build/resolution must be proven with emitted code.
- A save success without captured revision can incorrectly mark newer text clean.
- Captured revision alone cannot order save/reload or save/close operations that share the same text revision; all canonical document IO must use the same per-tab transaction owner.
- Releasing native close leases after discard but before unregister lets a queued autosave write a tab the user already chose to discard.
- Hash-only equality can produce a false clean result; exact saved checkpoint comparison is required.
- Domain projections that share mutable arrays/objects can leak write access to canonical state.
- Moving DTO ownership into domain would make renderer depend on internal session concepts and expand RF-101 into RF-202.
- Directly importing CodeMirror would violate the domain boundary and steal RF-201.
- Existing watcher ownership and sender validation gaps remain deferred and must not be silently folded into this task.
