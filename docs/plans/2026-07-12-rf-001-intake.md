# RF-001 Editing Behavior Baseline Intake

Date: 2026-07-12
Task: RF-001
Status: DEV_DONE — formal acceptance pending

## Goal

Freeze the intentional Markdown editing contract as typed source, selection, physical-line geometry, repeat-operation, and undo expectations before the editor foundation moves.

## In Scope

- Convert representative captured Typora oracle cases and current FishMark editing probes into typed behavior cases.
- Cover Enter, Backspace, Tab, Shift+Tab, ArrowUp, ArrowDown, selection, repeat, and undo contracts.
- Cover every required recursive container path plus representative depths 0 through 8.
- Classify desired behavior separately from current known defects.
- Register one test-harness scenario with command and container-path filtering.
- Update stable test cases and the editor-foundation progress record after fresh evidence exists.

## Out of Scope

- No editor command, parser, CodeMirror, IPC, CLI, or product behavior changes.
- No RF-002 or later refactor work.
- No screenshot or generated runtime artifact stored in the typed manifest.
- No claim that geometry or undo cases ran through the current Electron driver; that driver does not expose those assertions in RF-001.

## Accepted Harness Design

The existing scenario registry filters scenarios, not parameterized cases, and the current editor driver has no undo, geometry, or view-mode assertion commands. RF-001 therefore adds a typed case query and a deterministic scenario factory without expanding runtime editor or IPC surfaces. The registered default scenario describes the full corpus; callers can build the same scenario metadata for a command and/or exact container path through the exported filter API.

## Acceptance

- Every required command has a typed case at each of the ten recursive container paths.
- Depths 0 through 8, empty/whitespace/content lines, start/middle/end/range selections, and view-mode metadata are represented.
- Every case carries desired/known-defect classification and all required expectation fields.
- Known defects preserve the desired expectation separately from the observed current result.
- One `editor-behavior-matrix` scenario is registered and its case metadata can be filtered by command or container path.
- Focused and full project gates pass without runtime editor changes.

## Risks

- Treating a current implementation limitation as a desired editing rule.
- Freezing DOM class names instead of semantic physical-line geometry.
- Overstating execution coverage while the current driver cannot assert geometry or undo.
