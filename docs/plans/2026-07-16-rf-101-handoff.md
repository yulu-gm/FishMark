## Outcome

RF-101 now has one production, runtime-neutral `@fishmark/workspace-domain` package and one live main-owned `WorkspaceState`. The package owns canonical window, tab, document-session, text-buffer, revision, saved-checkpoint, ordering, move, detach, close, and immutable projection rules. Main maps those projections to the existing shared IPC DTOs at one explicit boundary.

The cutover is complete at development level:

- `src/main/workspace-service.ts` and its test are deleted;
- no service facade, compatibility alias, dual state, dead rollback path, or old exported session snapshot remains;
- main, application, close coordination, reload, file operations, and detach consume the package public entry;
- renderer/preload/shared IPC wire shapes and channels are unchanged;
- every asynchronous IO/lifecycle workflow captures canonical owner/revision state before waiting and fails closed when completion is stale;
- detach is a ready-gated transaction with bounded rollback/cleanup behavior.

This handoff does not declare architecture or task `PASS`, does not mark RF-101 `COMPLETE`, and does not start RF-102.

## Scope and final architecture

```text
renderer -> shared IPC DTOs -> preload -> main composition
                                      -> workspace IPC projection mapper
                                      -> main use cases / IO ports
                                      -> one @fishmark/workspace-domain WorkspaceState
```

Canonical invariants:

1. Markdown text is the only document truth.
2. Main owns the only live writable workspace state.
3. Domain code has no Electron, React, DOM, CodeMirror, filesystem, watcher, dialog, or IPC dependency.
4. `TextBuffer` values and domain projections are immutable and cannot be mutated back into canonical state.
5. Text changes advance revision once; identical content does not advance it.
6. `isDirty` is derived only from `revision !== savedRevision`.
7. Exact saved-text checkpoints make Undo/manual restoration to durable content clean immediately.
8. Save/reload/close/file/detach completion is bound to captured revision and ownership; mismatches fail closed without overwriting newer text.
9. Shared IPC wire contracts remain owned by `src/shared/workspace.ts`; main creates a mutable serializable DTO copy.
10. Consumers import only `@fishmark/workspace-domain`, never package internals.

## Manual acceptance draft

1. Start FishMark, create an untitled tab, type Markdown, save it, and confirm the tab becomes clean without text normalization.
2. Edit a saved document while a save is in flight. Confirm the newer edit remains visible and dirty after the earlier write completes.
3. Restore the document exactly to the last durable text through Undo or manual editing. Confirm it becomes clean without another disk write.
4. Open multiple tabs, reorder, move, and detach them. Confirm source/target active tabs and tab order remain consistent, and the detached tab is not lost if target-window readiness fails.
5. Trigger close on clean, dirty-save, dirty-discard, cancelled, failed-write, and edit-during-save paths. Confirm only the valid clean/durable state closes.
6. Reload an externally changed active document and confirm stale tab ownership/revision cannot replace a newer or different tab.
7. Run the zero-residue commands above and confirm the old service, obsolete types, runtime legacy state fields, and consumer deep imports remain absent.
