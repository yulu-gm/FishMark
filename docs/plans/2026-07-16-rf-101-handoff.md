## Outcome

RF-101 now has one production, runtime-neutral `@fishmark/workspace-domain` package and one live main-owned `WorkspaceState`. The package owns canonical window, tab, document-session, text-buffer, revision, saved-checkpoint, ordering, move, detach, close, and immutable projection rules. Main maps those projections to the existing shared IPC DTOs at one explicit boundary.

The cutover is complete at development level:

- `src/main/workspace-service.ts` and its test are deleted;
- no service facade, compatibility alias, dual state, dead rollback path, or old exported session snapshot remains;
- main, application, close coordination, reload, file operations, and detach consume the package public entry;
- workspace snapshot DTOs and channel names are unchanged; reload is hard-cut to `success(snapshot) | revision-stale`, while native-close REQUEST, CONFIRM, and COMPLETE carry one `requestId` end to end, with no compatibility route for either changed contract;
- Save, Save As, reload, and individual close share one main-owned per-document FIFO IO coordinator; ordinary Save keeps watcher begin/write/commit/recent/complete/resync in one lease, while unrelated tabs and high-frequency draft updates remain independent;
- draft updates are owner-aware without entering the IO queue: main derives `expectedWindowId` only from the invoking renderer, domain applies a compare-and-set, and stale source renderers can neither mutate canonical text/revision nor receive the new owner's projection;
- cross-window move and ready-time detach transfer use the exact same per-tab coordinator as document IO. Source ownership is revalidated inside the lease; detach waits for target readiness outside it, then atomically transfers the latest canonical session. Timeout, load failure, or target close while queued rejects detach and ready, destroys the target, and cannot create a domain window or main binding. A dedicated window-registration application captures the live sender-owned `BrowserWindow` and ID before ready, revalidates the same live identity after ready, and only then registers, binds, and focuses it; there is no sender-ID fallback;
- Save, Save As, and reload consume total domain mutation results. Owner/missing results throw rather than report false success or record a recent path. Reload revision staleness returns no projection and does not record recent; renderer retains its newer draft/external conflict, warns that retry is available, returns false, and keeps autosave/manual-save conflict protection active;
- native window close binds its frozen ordered owner/revision confirmation to one `{ windowId, requestId }` generation and allows only one confirmation scope. Its 15-second timer covers transport through renderer draft flush and the first exact CONFIRM, then is disarmed while native prompt/Save As may continue. After that scope finishes, a separate watchdog bounds the wait for COMPLETE; renderer abort/destruction/window close or missing COMPLETE settles fail-closed, while the stable multi-tab lease still waits for active work to drain before release.

This handoff does not declare architecture or task `PASS`, does not mark RF-101 `COMPLETE`, and does not start RF-102.

## Scope and final architecture

```text
renderer -> shared IPC DTOs -> preload -> main composition
                                      -> workspace IPC projection mapper
                                      -> main use cases / per-document IO coordinator
                                      -> one @fishmark/workspace-domain WorkspaceState
```

Canonical invariants:

1. Markdown text is the only document truth.
2. Main owns the only live writable workspace state.
3. Domain code has no Electron, React, DOM, CodeMirror, filesystem, watcher, dialog, or IPC dependency.
4. `TextBuffer` values and domain projections are immutable and cannot be mutated back into canonical state.
5. Text changes advance revision once; identical content does not advance it.
6. `isDirty` is derived only from `revision !== savedRevision`.
7. Exact saved-text checkpoints make Undo/manual restoration to durable content clean immediately.
8. Captured ownership/revision/checkpoint guards make a single completion fail closed; they do not define ordering between distinct IO operations that share a revision.
9. Save, Save As, reload, individual close, cross-window move, and ready-time detach transfer are serialized per tab through one main-owned FIFO coordinator. An ordinary Save includes watcher begin/write/commit/recent/complete/resync in that lease; different tabs proceed independently.
10. `updateDraft` is not queued, but it is an owner compare-and-set. Main derives expected ownership only from the IPC sender, and stale mutation results are rejected without returning another window's projection.
11. Save, Save As, and reload handle total mutation results: owner/missing is an operation failure. Reload's revision-only race returns `revision-stale` without a projection; only an applied reload may record recent, return a snapshot, clear conflict, and report success.
12. Native window close holds a deduplicated, stable-order multi-tab lease across the renderer handshake. The broker returns `{ requestId, result, drained }`; REQUEST, CONFIRM, and COMPLETE carry the exact window/request generation, and only the first exact CONFIRM may begin confirmation. That begin disarms the 15-second transport timer, so prompt/Save As duration is unbounded by transport. When active confirmation ends without COMPLETE, an independent post-confirm watchdog fails closed and releases retained state; COMPLETE and abort cancel it exactly once. Renderer abort/destruction/window close removes pending state fail-closed, but `drained` waits for the active confirmation handler and main awaits both promises before the application may release the lease. The coordinator stops inactive work after prompts and before/after writes, and the application revalidates exact tab order, owner, and revision after COMPLETE.
13. Detach waits for target readiness without holding the tab lease. It acquires the same lease as IO only for transfer, revalidates source owner inside it, and moves the current latest canonical session—including edits made while waiting—atomically. Timeout, load failure, or target close while queued stores the authoritative lifecycle error on the in-flight ready transaction; both promises reject, the target is destroyed, and source content/owner/last-focus plus domain/main window registries remain unchanged.
14. Window registration is one explicit application transaction: validate the sender and owner, capture the owner object and ID, await detach readiness, revalidate the same live sender/owner object/ID, then register, bind, and focus in that order. Any missing, destroyed, changed, or failed-ready boundary exits before those side effects.
15. Shared workspace DTO, reload result, and native-close request contracts remain owned by `src/shared/workspace.ts`; main creates mutable serializable projection copies, accepts no legacy bare reload snapshot, and accepts no parameterless close-confirmation form. Test fixtures use that exact reload union through `satisfies`, not widening assertions.
16. Consumers import only `@fishmark/workspace-domain`, never package internals.

- Package boundary: tests were introduced before the package modules/public entry existed, then reached green with the real local production dependency, CommonJS/declaration build, runtime smoke verifier, active manifest rule, immutable string `TextBuffer`, and public-entry-only imports.
- Document session: review exposed missing equal-content reload mutation evidence and a stale/mismatched save path that could falsely clean current text. - Workspace state: the initial spec review found insufficient inactive activation, reorder payload, cross-window move, and detach activation assertions. Four mutation-proof tests closed those gaps. Final workspace-state coverage was 25 tests and the then-combined domain suite 67/67.
- Main hard cutover: independent spec and quality review drove explicit domain-to-IPC mapping and then closed stale IO owner/revision handling, detach source-owner/ready ordering, original error preservation, and bounded lifecycle cleanup. Detach moves the latest canonical session only after ready-time owner revalidation rather than rejecting a revision that changed while waiting.
- Architecture closure: the first RED set proved a late source renderer could cross an ownership transfer and mutate/receive the target projection. Further RED tests exposed move/detach outside the IO transaction, false-success Save/Save As/reload after owner loss, and a missing-COMPLETE path that retained the close lease forever. GREEN uses real move and detach transitions, all four save-first/move-first/reload-first/detach-first orderings on the shared coordinator, total mutation results, and a two-phase close liveness policy. The transport timer ends at the first exact confirmation begin, active native UI remains unbounded, and only the post-scope COMPLETE wait has the independent watchdog.
- Final acceptance-blocker closure: RED proved a deferred reload followed by a newer draft was returned as success and cleared external-conflict protection, while queued detach cancellation rejected detach but let `markWindowReady` resolve and permitted later binding. GREEN carries explicit reload staleness end to end, removes `allowRevisionChanged`, records recent only after an applied domain reload, and makes timeout/close/load-fail reject ready with no target domain/main registration. The normal reload-success/conflict-clear and normal detach-transfer paths remain green.
- Live-window boundary closure: RED first failed because no independently executable registration application existed; a second wiring RED proved main had not adopted it. GREEN covers normal side-effect order plus null, destroyed, disappeared, changed-object, changed-ID, and failed-ready cases across both sides of the await, with zero register/bind/focus calls on every rejection. Main now composes this application instead of embedding the lifecycle rule, and the remaining workbench reload fixture is compile-time bound to the exact discriminated result.

## Manual acceptance draft

1. Start FishMark, create an untitled tab, type Markdown, save it, and confirm the tab becomes clean without text normalization.
2. Edit a saved document while a save is in flight. Confirm the newer edit remains visible and dirty after the earlier write completes.
3. Start reload and then type a newer draft before the deferred disk read returns. Confirm reload reports a retryable warning, keeps the draft and external-conflict banner, does not add recent history, blocks autosave, and routes manual Save through conflict protection. Retry without a concurrent edit and confirm the disk snapshot applies and clears the conflict. Also reverse Save/reload ordering and confirm their shared lease preserves clean memory/disk agreement.
4. Choose discard on an individual dirty-tab close while an autosave is queued; confirm the tab closes and the queued save never writes. Reverse the order; confirm close waits for Save and then closes the clean tab without another prompt.
5. During native window close, choose discard while an autosave is queued; confirm no write occurs before the real window unregister. Cancel the close and confirm the queued save resumes normally.
6. Restore the document exactly to the last durable text through Undo or manual editing. Confirm it becomes clean without another disk write.
7. Open multiple tabs, begin a detach, and edit the tab while the target is becoming ready. Confirm the tab stays in the source until ready, then moves with the latest edit after source-owner revalidation. While transfer is queued behind Save/reload, separately trigger timeout, load failure, and target close; each must reject ready/detach, destroy the target, retain source/last-focus, and leave no target workspace binding.
8. Trigger close on clean, dirty-save, dirty-discard, cancelled, failed-write, and edit-during-save paths. Confirm only the valid clean/durable state closes.
9. Run the zero-residue commands above and confirm the old service, obsolete types, runtime legacy state fields, and consumer deep imports remain absent.
10. Move or detach a dirty tab from window A to B, then force A's delayed draft sync. Confirm the invoke rejects and B retains exactly its current text/revision.
11. Begin native close, let the native confirmation finish, and suppress COMPLETE. Confirm the independent post-confirm watchdog eventually fails closed; repeat with a native prompt held open beyond the timeout budget and confirm no timer fires while that scope remains active.
