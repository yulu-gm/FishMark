## 2026-07-28 physical file identity closure

The final architecture blocker is closed in execution. `FileIdentity` is now an opaque pair of canonical location identity and filesystem object identity. Main resolves the location from `realpath` (or the deepest existing ancestor for a prospective Save As target) and uses reliable `stat({ bigint: true })` `dev + ino` values for the object; when the filesystem cannot expose a reliable object id, it explicitly falls back to the canonical path. Only Windows paths are case-folded. `WorkspaceState` owns separate global location-to-tab and object-to-tab registries, so both a replaced inode at the same path and hard-link aliases of one inode remain single-owner.

Open, Save, Save As, reload, and close-save use separate typed coordinators and the fixed lock order `tab lease -> location lease -> object lease -> watcher write -> filesystem IO -> guarded domain commit`. Save As selects outside the ordinary tab lease, reserves the prospective location, re-resolves before writing, and for a new file resolves and locks the resulting object before owner check and atomic commit. Existing-target identity changes fail before writing; ordinary Save fails closed on inode replacement, while explicit Reload may migrate the object identity atomically at the same location. Cross-window duplicate open releases every identity/tab lease before asking the owner renderer to activate the tab. Renderer snapshot writers use one strict per-window FIFO and a per-tab exact-ack draft outbox. Every dispatched response advances the renderer's canonical-main reference; non-replaceable operations remain ordered, activation alone is latest-intent supersedable, and an unknown activation transport result is reconciled with `getWorkspaceSnapshot`. A confirmed target is never followed by an unsynchronized rollback activation: draft failure leaves the canonical target visible and the source draft queued for later sync. Main then reacquires the tab lease, revalidates typed ownership, the exact live `BrowserWindow` instance, and the requested active tab before focus. A negative confirmation is retried only when ownership changed, while an unchanged owner or newer local tab intent fails without replay. The requester still receives only `focused-existing` and never receives another renderer's projection.

## Outcome

RF-101 now has one production, runtime-neutral `@fishmark/workspace-domain` package and one live main-owned `WorkspaceState`. The package owns canonical window, tab, document-session, text-buffer, revision, saved-checkpoint, ordering, move, detach, close, and immutable projection rules. Main maps those projections to the existing shared IPC DTOs at one explicit boundary.

The cutover is complete at development level:

- `src/main/workspace-service.ts` and its test are deleted;
- no service facade, compatibility alias, dual state, dead rollback path, or old exported session snapshot remains;
- main, application, close coordination, reload, file operations, and detach consume the package public entry;
- workspace snapshot DTOs and channel names are unchanged; reload is hard-cut to `success(snapshot) | revision-stale`, while native-close REQUEST, CONFIRM, and COMPLETE carry one `requestId` end to end, with no compatibility route for either changed contract;
- Save, Save As, reload, and individual close share one main-owned per-document FIFO IO coordinator; ordinary Save keeps watcher begin/write/commit/recent/complete/resync in one lease, while unrelated tabs and high-frequency draft updates remain independent;
- renderer/preload Save, Save As, and reload commands carry only `tabId`. Main derives ordinary-save/reload targets and Save As's dialog default from the lease-time canonical checkpoint; a missing path fails closed. The internal filesystem adapter has its own explicit `{ tabId, path, content }` input and does not extend a renderer DTO;
- successful open/save adapter documents have a non-empty persisted `path: string` contract, while nullable paths exist only in workspace/domain projections for untitled sessions. Save, Save As, reload, and close-save validate untrusted adapter results at runtime before domain mutation. Ordinary Save/reload lock path, name, and saved identity to the captured canonical checkpoint; Save As accepts a new non-empty path only when the returned content exactly matches the captured text;
- watcher sync is a no-input renderer intent. Main derives a live sender-owned window, and the stateless application immediately projects its canonical active path into the infrastructure service without a long-I/O queue. Each per-`webContents` controller is the sole owner of desired path/path epoch, latest sync admission, entry identity, monotonic observation identity, exact internal-write identity, and a destroy tombstone. All stat work runs outside state mutation; completion may perform only a short live-controller/exact-identity CAS. A newer same-path/different-path sync or callback can finish while A is deferred, and only the latest normal observation may update the baseline or emit. Begin-write follows superseding admissions until the latest settles, invalidates older observations, and installs a write token; complete updates/clears only that exact transaction, while callbacks captured anywhere inside the write remain silent. Watch create/replace/rollback/destroy commit authoritative state before safe close, so close/report exceptions cannot leak or resurrect a controller. Callback rejections remain contained and different windows remain parallel;
- draft updates are owner-aware without entering the IO queue: main derives `expectedWindowId` only from the invoking renderer, domain applies a compare-and-set, and stale source renderers can neither mutate canonical text/revision nor receive the new owner's projection;
- renderer workspace mutations are coordinated by a focused `WorkspaceMutationCoordinator`, while `WorkspaceDraftOutbox` keeps unsent text isolated per tab and rejects stale acknowledgements. The current file-open dialog remains inside the strict FIFO transaction for correctness; RF-102 may split dialog preparation from commit to reduce head-of-line waiting, but must preserve the same commit order and outbox guarantees;
- reorder, cross-window move, and ready-time detach transfer use the exact same per-tab coordinator as document IO. Main derives reorder ownership from the invoking renderer and the domain returns a total applied/stale result, so an old owner cannot mutate or receive the target window. Transfer source ownership is revalidated inside the lease; detach waits for target readiness outside it, then atomically transfers the latest canonical session. All concurrent ready notifications share one in-flight Promise and cannot register early. Timeout, load failure, or target close while queued rejects detach and every ready caller with one authoritative error, destroys the target once, and cannot create a domain window or main binding. A dedicated window-registration application captures the live sender-owned `BrowserWindow` and ID before ready, revalidates the same live identity after ready, and only then registers, binds, and focuses it; there is no sender-ID fallback;
- Save, Save As, and reload consume total domain mutation results. Owner/missing results throw rather than report false success or record a recent path. Reload revision staleness returns no projection and does not record recent; renderer retains its newer draft/external conflict, warns that retry is available, returns false, and keeps autosave/manual-save conflict protection active;
- native window close binds its frozen ordered owner/revision confirmation to one `{ windowId, requestId }` generation and allows only one confirmation scope. Its 15-second timer covers transport through renderer draft flush and the first exact CONFIRM, then is disarmed while native prompt/Save As may continue. After that scope finishes, a separate watchdog bounds the wait for COMPLETE; renderer abort/destruction/window close or missing COMPLETE settles fail-closed, while the stable multi-tab lease still waits for active work to drain before release.

## Scope and final architecture

```text
renderer -> shared IPC DTOs -> preload -> main composition
                                      -> workspace IPC projection mapper
                                      -> main use cases / per-document IO coordinator
                                      -> one @fishmark/workspace-domain WorkspaceState
```

Canonical invariants:

1. Markdown text is the only document truth.
2. Main owns the only live writable workspace state.
3. Domain code has no Electron, React, DOM, CodeMirror, filesystem, watcher, dialog, or IPC dependency.
4. `TextBuffer` values and domain projections are immutable and cannot be mutated back into canonical state.
5. Text changes advance revision once; identical content does not advance it.
6. `isDirty` is derived only from `revision !== savedRevision`.
7. Exact saved-text checkpoints make Undo/manual restoration to durable content clean immediately.
8. Captured ownership/revision/checkpoint guards make a single completion fail closed; they do not define ordering between distinct IO operations that share a revision.
9. Save, Save As, reload, individual close, reorder, cross-window move, and ready-time detach transfer are serialized per tab through one main-owned FIFO coordinator. An ordinary Save includes watcher begin/write/commit/recent/complete/resync in that lease; different tabs proceed independently.
10. `updateDraft` is not queued, but it is an owner compare-and-set. Main derives expected ownership only from the IPC sender, and stale mutation results are rejected without returning another window's projection.
11. Save, Save As, and reload handle total mutation results: owner/missing is an operation failure. Reload's revision-only race returns `revision-stale` without a projection; only an applied reload may record recent, return a snapshot, clear conflict, and report success.
12. Native window close holds a deduplicated, stable-order multi-tab lease across the renderer handshake. The broker returns `{ requestId, result, drained }`; REQUEST, CONFIRM, and COMPLETE carry the exact window/request generation, and only the first exact CONFIRM may begin confirmation. That begin disarms the 15-second transport timer, so prompt/Save As duration is unbounded by transport. When active confirmation ends without COMPLETE, an independent post-confirm watchdog fails closed and releases retained state; COMPLETE and abort cancel it exactly once. Renderer abort/destruction/window close removes pending state fail-closed, but `drained` waits for the active confirmation handler and main awaits both promises before the application may release the lease. The coordinator stops inactive work after prompts and before/after writes, and the application revalidates exact tab order, owner, and revision after COMPLETE.
13. Reorder uses a total owner-aware domain mutation behind the shared tab lease. Main supplies only the sender-derived expected owner; stale/missing requests throw at the application boundary without returning a foreign projection.
14. Detach waits for target readiness without holding the tab lease. Its pending state owns one lazily created ready Promise reused by every concurrent caller. It acquires the same lease as IO only for transfer, revalidates source owner inside it, and moves the current latest canonical session—including edits made while waiting—atomically. Timeout, load failure, or target close while queued stores the authoritative lifecycle error; detach and every ready caller reject, the target is destroyed once, and source content/owner/last-focus plus domain/main window registries remain unchanged.
15. Window registration is one explicit application transaction: validate the sender and owner, capture the owner object and ID, await detach readiness, revalidate the same live sender/owner object/ID, then register, bind, and focus in that order. Any missing, destroyed, changed, or failed-ready boundary exits before those side effects.
16. Shared workspace DTO, reload result, and native-close request contracts remain owned by `src/shared/workspace.ts`; main creates mutable serializable projection copies, accepts no legacy bare reload snapshot, and accepts no parameterless close-confirmation form. Test fixtures use that exact reload union through `satisfies`, not widening assertions.
17. Consumers import only `@fishmark/workspace-domain`, never package internals.
18. Public Save, Save As, reload, and watch commands cannot carry a renderer-selected path. File identity is read from canonical session/window state at the main application boundary; the obsolete domain `getTabPath` convenience surface is deleted.
19. A successful filesystem adapter document is persisted and therefore has a non-empty string path. Untitled/null path remains a workspace/domain concept, not a successful open/save result. Main validates adapter objects at runtime and never lets adapter-returned ordinary-save/reload identity replace the captured canonical path/name/content.
20. The watcher application is stateless and immediately maps the current canonical active path to one infrastructure intent. Infrastructure is the sole state owner and uses desired path/path epoch, exact latest sync admission, entry identity, monotonic observation identity, exact write identity, and a destroy tombstone. Stat I/O never owns a state queue; each completion performs a short exact CAS. Superseded sync admission wakes begin-write immediately, latest-initiated normal callback wins, own-write callbacks remain silent, and safe close cannot roll authoritative state back. No application/state Promise queue, lock inversion, double-enqueue cycle, stale baseline overwrite, or slow-stat head-of-line blocking remains.
