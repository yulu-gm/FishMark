## 实现与落点

- `src/main/main.ts` 保留 dependency construction、workspace/native-close/recovery 生命周期及注册调用。workspace command DTO mapping、preferences/recent/fonts/themes/export/clipboard/external/updates/test handlers 各自进入 `src/main/ipc/register-*-handlers.ts`，没有通用路由、兼容 facade 或新业务 owner。
- `ipc-lifecycle.ts` 只记录成功注册的 channel，拒绝重复注册，不接管外部 handler，quit 时幂等释放并拒绝旧 callback。
- `ipc-sender.ts` 验证 live BrowserWindow/WebContents 的真实身份、当前 mainFrame、非 detached 状态、该窗口 main-owned entry URL 与 runtime allowlist。`runtime-windows.ts` 私有 WeakMap 提供 mode，不读取 IPC 自报权限。
- 原 `register-workspace-handlers.ts` **字节不变**。新增外层 edit registrar 将每次 invocation 的 frame/runtime 检查带入原 queued authorization，仍使用原 apply/flush、held close lease、projection/ACK 与错误结果协议。workspace commands 继续调用原 application，owner/CAS/moved-tab/native-close 逻辑没有重写。
- workspace readiness await 后再次授权，异步服务响应前再次授权。native-close completion 在调用 broker 前已验证，完成后可合法销毁 sender，所以无数据完成响应不做错误的“必须仍活着”要求；新增针对该情形的回归。
- preload 复用原 `product-api.ts`，独立 `test-api.ts` 只在单个明确 main bridge argument 为 editor-test/test-workbench 时构造并 expose。缺失/非法/重复参数与单独 runtime label 都是 product。main 每个窗口显式传入 bridge mode，packaged main 固定 editor/product。
- test registration 仅 dev workbench 初始化；scenario 管理只允许 workbench，command completion 只允许该 session 的真实 editor-test webContents。移除 preload 类型 re-export 与无消费者的重复 runtime parser，测试改为真实 builder method contract。
- CI focused 增加所有 IPC/preload、新 shared bridge-mode 与 runtime/session 测试。现有 native safety 和正式 behavior 步骤、Linux CI opt-in no-sandbox 三条件、timeouts、cases、oracles、budgets 均未修改。
