# 编辑体验向 Typora 对齐

目标：在保留 Markdown 源码权威和现有技术栈的前提下，让日常编辑尽量接近本机 Typora 1.14.15。参考审查报告 `reports/reviews/2026-11-13-typora-editing-comparison.md`。以下是持续任务清单，不能用其中一项通过代表整个目标完成。

## 验收范围

- [ ] 段落：Enter 创建段落、Shift+Enter 段内换行；已有换行两侧行为一致；连续空段落按语义单位增删。
- [ ] 删除：正文前向/后向删除一致；引用、列表、标题、代码块和表格边界不误删结构。
- [ ] 空行：显示、光标导航、删除及保存重开使用一致的分隔规则。
- [ ] 导航：长短长行保持目标列，自动折行按视觉行移动；跨块、反向选区和 emoji 边界正确。
- [ ] 输入法：正文及表格候选确认不触发结构命令；组合期间切换、保存、撤销保留正确内容。
- [ ] 粘贴：异步图片不替换错内容；纯文本入口保留；HTML 转 Markdown 与表格矩形粘贴有明确策略。
- [ ] 表格：多行单元格内部导航、跨格导航、插入行列、粘贴和撤销一致。
- [ ] 格式与代码：选区格式切换、可选配对输入、代码块语言与缩进行为自然。
- [ ] 搜索与滚动：隐藏标记及表格搜索定位明确；异步预览、宽表格和长文档不造成光标跳动。
- [ ] 历史：上述结构操作、粘贴、输入法提交可按用户操作撤销重做，并恢复选区。

## 验证方式

纯语义命令用模型测试检查源码与选区；涉及字体、折行、滚动和原生键盘的操作用 Electron 测试。Windows 输入法候选行为需要真实输入法验证，合成事件不作为替代。Typora 安装包静态分析是行为依据之一，不替代尚未完成的界面验证。

每批修改记录实际测试结果，build、lint、typecheck 和相关回归通过后提交。保留未完成项，不因局部通过而宣布整体对齐完成。

普通纯空行的交替角色由 `canonical-semantic-lines.ts` 一次生成。渲染层直接读取语义行角色，删除了独立的空行奇偶计算和块前分隔扫描；语义上下导航读取同一模型。文末没有换行符的空行保留为输入位置，含空格的行不折叠，代码/数学/列表/引用内部仍由对应块规则决定。

## 进展：表格多行编辑与矩形粘贴

活动单元格中的 Markdown 硬换行投影为真实视觉行，保留原始 `<br>` 标记及源码偏移；代码中的字面 `<br>` 不转换。上下键先移动格内视觉行，到首尾行才跨格。非空选区先在当前格内收起，防止 Chromium 默认移动跳到相邻编辑区；Shift 扩选和组合态保持各自处理。选区监听在失焦和 widget 销毁时清理。

HTML 表格和 TSV 粘贴按矩形写入，必要时扩展行列。HTML 只解析文本，不插入剪贴板 DOM；支持合并单元格占位。TSV 支持引号内制表符/换行、转义引号和末尾空单元格。单元格内部换行写为 `<br>`，管道正确转义。未覆盖单元格保留原始转义和行内代码，引用容器、CRLF、无表头表格与列对齐得到保留。粘贴是独立的一次撤销操作，普通单行文本继续走单格输入。

## 进展：跨块删除保护

正文与代码围栏、表格相邻时，Delete/Backspace 先清理可移除的多余分隔，再把光标移到对面的可编辑内容，不把围栏、语言或表格语法拼进正文。代码正文首尾也不会吞掉开闭围栏；代码内部仍正常合并两行。表格和缩进代码保留必要分隔。正文和 ATX 标题合并时处理隐藏的尾部 `###`，正文接在标题文字之后、尾标记之前。

父列表项带子项、任务标记或多行引用时，避免只删除父级前缀而改变后续行的归属；从嵌套子项或引用离开时也不把外部正文吸入容器。保留同级普通列表叶子的合并行为、非空选区直接删除，以及 CRLF 完整性。这是对已复现结构损坏的修复，未声称所有跨容器光标落点与 Typora 完全一致。

## 进展：表格搜索命中反馈

搜索在可证明源码到 DOM 文本映射时使用原生文字范围高亮；同一格里的多个命中，以及 `<br>` 后的命中可以区分。高亮不改 DOM 内容和浏览器选区，不抢搜索框焦点；多个编辑器只清理各自拥有的范围。预览中的换行保留隐藏源码标记，让搜索和滚动共用同一映射。隐藏标记或无法证明映射的内容仍以整格提示；分隔符或跨格范围以表格轮廓和“切换源码视图”提示表达。

真实 Electron 用例确认第二个命中在下一视觉行、焦点保留、查询清空后高亮清理、跨格源码提示；已检查截图，只有第二行的匹配文字着色。没有将隐藏语法当成可见字符。

## 进展：可配置配对输入

偏好设置新增“编辑 → 自动配对”，分别控制括号/引号与 Markdown 符号，默认前者开启、后者关闭。设置即时更新现有编辑器，并随配置保存；旧版配置迁移补默认值，IPC 只接受明确布尔值。源码视图也使用同一设置，组合输入和只读状态不会触发配对。

普通配对、包裹选区和配对退格复用 CodeMirror，保留反向选区和原有历史。Markdown 特例包括连续星号形成加粗、三反引号形成围栏，以及依照 canonical AST 的完整闭标记范围跳过闭符。列表/引用内的围栏读取内容起点，代码正文按字面输入 Markdown 符号；不会把普通星号或开标记误当闭符吞掉。

表格通过单次单元格投影复用同一配对算法，实际写入仍由表格命令生成源码事务，保留管道转义、隐式缺失单元格的结构建立及文档历史。没有另存一份单元格文档或撤销栈。普通字母提前退出配对入口，避免无效表格投影。

真实连续输入发现设置关闭动画结束时会把焦点从正文抢回设置按钮。现在延迟恢复只在焦点未被用户重新选择时执行；关闭期间重新打开设置也会取消旧恢复。补充正文和搜索框两种新焦点、原入口恢复和重新打开测试。

## 进展：容器内网页粘贴

HTML 转换结果在同一列表项或引用容器中，按语义容器的前缀补齐后续行；块片段与保留下来的前后文字分段。任务框不计入续行缩进，保留原子列表和兄弟项，沿用原文 LF/CRLF。触及结构标记或跨不同容器的复杂选区返回同次剪贴板的纯文本，避免将转换后的复杂 Markdown 直接套进无法确认的容器。

补齐省略前缀的续行行首：粘贴列表或围栏时显式补回所在容器，并隔开前段；原文只有 `-`、`12.` 或 `> -` 时，补标记后的间距及对应续行缩进。模型测试重新解析结果，验证子列表、保留正文与围栏的归属及闭合。跨容器回退纯文本仅承诺使用剪贴板原文，不承诺任意纯文本都保持原结构。

新增 Electron 场景覆盖列表项中间的多段正文、引用内列表、引用列表内代码片段，并检查光标、反向选区撤销、重做及保存重开。事件由渲染进程的 ClipboardEvent 提供，不将其等同于任意应用的系统剪贴板验证。

## 进展：清空表格后的组合输入

新增配对回归复现了另一个输入问题：清空单元格后，DOM 只有占位 `<br>`，光标位于它之后；Chromium 合成输入 `[` 再提交同值时没有结束组合区，DOM 出现 `[[`，源码继续等待组合结束。初始空单元格和不安装产品监听器的原生编辑区可正常提交。事件及 DOM 变更记录排除了失败期间脚本重设选区的情况。

修正源码偏移 0 到空格 DOM 的映射，并在非组合删除后将占位 BR 后的折叠光标归到前方。只处理源码为空且仅有单个 BR 的单元格，不更改真实硬换行、范围选区或正在进行的组合。没有绕过 compositionend 强制提交，也没有合成产品结束事件。修复后同值提交功能断言通过；真实 Windows 输入法的候选窗口、保存和切换仍需单独验证。
