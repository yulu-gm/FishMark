# RF-204 Intake — Hard Cutover from Full Draft Synchronization

**Task:** `RF-204 — Hard cutover from full draft synchronization`

**Date:** 2026-08-13

**Status:** `IN_PROGRESS`

## Goal

Every document change uses revisioned edit batches. The legacy full-draft synchronization
channel (`UPDATE_WORKSPACE_TAB_DRAFT_CHANNEL` / `updateWorkspaceTabDraft`) is deleted end to
end — shared contract, preload bridge, main IPC handler, workspace-application use case, and
the renderer draft outbox/local mutation paths — so milestone 2 has no dual state path. This
also closes the RF-203-deferred quality-review items that are owned by this deletion (the
dormant full-draft test driver and the application-level `updateDocumentDraft` use case).

## Architectural decision

- Delete the full-draft transport completely, not keep it dormant. RF-203 already proved the
  production editor reaches only the revisioned frame path; RF-204 removes the dormant code so
  the retired symbols cannot be reintroduced.
- Delete the application-level `updateDocumentDraft` use case and its `drafts` port. Its only
  production caller is the main IPC handler being deleted. The domain-level `WorkspaceState
  .updateTabDraft` remains as a domain capability exercised by save/close tests and is not a
  transport; RF-301+ decides its long-term fate as part of main save/recovery redesign.
- Replace test mocks of the retired bridge with revisioned apply/flush assertions or delete
  them where they only drove the dormant legacy path. Test drivers (`editor-test-driver`) and
  the test workbench route through the same revisioned application commands.
- Add a fail-closed architecture test that forbids the retired channel/symbol names in
  production sources.

## In scope

- Delete `UPDATE_WORKSPACE_TAB_DRAFT_CHANNEL` and `UpdateWorkspaceTabDraftInput` from
  `src/shared/workspace.ts`.
- Delete `updateWorkspaceTabDraft` from `src/shared/product-bridge.ts` and
  `src/preload/product-api.ts` (and the channel/type imports).
- Delete the `UPDATE_WORKSPACE_TAB_DRAFT_CHANNEL` IPC handler, `createUpdateDocumentDraft`
  composition, and the `drafts` port wiring from `src/main/main.ts`.
- Delete `packages/workspace-application/src/update-document-draft.ts`, its index export, the
  `updateDocumentDraft` method, and the `drafts` port from `workspace-application.ts`.
- Delete the renderer legacy draft path: `recordEditorChange`, `WorkspaceDraftOutbox`,
  `captureCurrentEditorContent`, and the legacy `drainTab`/`drainAllDrafts`/`syncDraftEntry`
  branches from `workspace-renderer-application.ts`; delete `workspace-draft-outbox.ts`; delete
  `updateDraft` from `useWorkspaceController.ts`.
- Replace/delete tests that mock the retired bridge; route test-driver and test-workbench
  fixtures through revisioned commands.
- Add an architecture test forbidding the retired channel/symbol names.

## Out of scope

- Domain `WorkspaceState.updateTabDraft` removal — it is a domain capability, not the transport;
  RF-301+ owns main save/recovery redesign.
- RF-203-deferred transport deadlines (apply/flush port timeouts) and blocked-queue UI retry —
  those are robustness items, not the full-draft deletion; they may be addressed in a follow-up
  RF-204-adjacent slice or a later task, but are not this deletion's gate.
- Main save/recovery redesign, per-document watch registry, recovery journals (RF-301+).
- Parser, recursive Markdown model, semantic commands, document cache (RF-401+).
