# RF-506 intake — Semantic engine hard cutover

日期：2026-09-18。前置 `RF-HARDEN-001` 与 `RF-601` 均已 `COMPLETE`/`PASS`；本任务不再有未满足的依赖。

## Task

`RF-506 — Semantic engine hard cutover`（editor-foundation M5 最后一个任务）

## Goal

把每一个生产消费者（键盘、菜单、工具栏、表格 widget、测试驱动器）都切到经过验证的 `@fishmark/editor-model` + `@fishmark/codemirror-adapter` 路径，用真实运行时行为证明执行的是新引擎，然后删除旧语义引擎、旧物理行模型与重复解析工具，使**只剩一套纯语义引擎**。

## In scope

- 在 `packages/editor-core/src/extensions/markdown.ts` 中安装 `@fishmark/codemirror-adapter` 的 `editorStructureCacheField`/`compositionStateField`，并让键位绑定经 adapter 的 `prepareCommand`/`recordEditorDispatch` 执行语义 plan。
- 重写 `packages/editor-core/src/commands/codemirror-markdown-command-adapter.ts`，使命令decision 全部来自 `@fishmark/editor-model`；不再保留 `editor-core` 自己的语义判定。
- `src/renderer/code-editor.ts`：把 `pressEnter`/`pressBackspace`/`pressTab`/`pressArrowUp`/`pressArrowDown`、表格操作与 `insertText` 路由到新路径；保留既有对外的 controller 契约与 frame 上报（`onDocumentChangeFrame`）语义。
- `src/renderer/editor-test-driver.ts` 与正式行为语料入口使用同一新路径。
- 删除：`packages/editor-core/src/commands/{line-parsers,list-utils,list-edits,markdown-commands,semantic-context,semantic-edits,table-context,table-edits,toggle-*,blockquote-commands,code-fence-commands,list-commands,table-commands,codemirror-markdown-commands}.ts` 中在切换后无调用者的部分；`packages/editor-core/src/{physical-editing-document,structural-line-model,list-utils}.ts`；`packages/editor-core/src/context/{editor-semantic-context,block-tree,block-path}.ts` 中与新引擎重复的部分。
- 为已退休的 editor-core 语义加入 forbidden imports / residue 断言（architecture guard）。
- 用新消费路径跑**完整**运行时行为语料（全部检查点，而非只回放首个检查点），外加连续编辑、撤销/重做、表格 focus、源码模式切换、延迟确认与组合输入。
- 删除前记录候选运行时性能与几何证据。

## Out of scope

- 视口装饰迁移、render plan、widget 交互注册表：属 RF-602/603/701。
- `packages/editor-core` 整包删除与 renderer 编辑器工厂迁移到 adapter：属 RF-604。本轮只做**语义**归属切换，装饰/交互仍可留在 editor-core。
- 共享 presentation/export/outline/metrics 收敛：属 RF-701/702/703。
- 按键到绘制的最终性能预算与 Playwright 数据安全套件：属 RF-901/902。

## Acceptance

- 键盘/菜单/工具栏/表格 widget/测试驱动器五类入口都由证据证明到达新引擎（不是只改一处）。
- `npm run test:editor-behavior` 对全部检查点执行且无回归；已知缺陷按原样保留、不得重新归类为期望行为。
- `src/renderer/code-editor.test.ts` 的全部既有行为在新路径下通过，或缺口被作为明确缺陷报告而不是改写期望。
- 撤销/重做在自动结构补全与延迟确认下正确；组合输入期间不做基于中间文本的结构决策。
- 旧语义模块删除后无调用者、无残留 import；architecture guard 对退休符号 fail-closed。
- 候选路径性能不低于已记录的 RF-601 证据：普通纯文本输入零 full parse；结构变更给出显式原因与实测代价。
- `npm run lint`、`npm run typecheck`、`npm test`、`npm run build`、正式行为语料全绿。
- 同步 `docs/test-report.md`、`reports/task-summaries/RF-506.md`、`docs/progress.md`、`MVP_BACKLOG.md`、`docs/decision-log.md`，并写人工验收步骤。

## Risks

- 极高风险面：IME、光标几何、undo/redo、autosave、round-trip、跨平台（Windows 为主）。这些正是 roadmap 要求以完整语料证明的部分。
- 删除量约 8.2k 行；必须先用真实运行时证据证明新路径正确，再删除，禁止以“删了多少行”作为成功指标。
- 菜单/工具栏/表格 widget 入口分散，容易只改键盘路径就宣称完成；验收必须逐入口证明。
- 行为语料存在 534 条已知缺陷；不得为了让新路径通过而把缺陷改写成期望行为。
- 需要在同一 diff 内保持 `src/renderer/code-editor.ts` 的对外契约不变，否则 RF-601 的队列集成与 RF-101 的 transition/barrier 逻辑会连带回归。
