## Outcome

This correction slice makes the RF-001 corpus honest and structurally usable, but it does not claim the task exit.

The typed manifest now separates desired contract sources from current implementation evidence. Every evidence aspect is represented by a typed `verified-probe`, `verified-test`, or `coverage-gap` entry. A roadmap paragraph can define a desired contract, but it can no longer masquerade as current execution evidence. Because the current driver cannot execute the complete source/selection/semantic-geometry/repeat/undo/view-mode matrix, RF-001 has returned from `DEV_DONE` to `IN_PROGRESS`.

No product editor command, parser, CodeMirror adapter, IPC, test driver, or runtime behavior changed in this slice.

## What Changed

- Split the corpus into a package-local executable model, named-probe cases, recursive-container cases, and a composed manifest; the repository fixture files remain stable public entry points.
- Added a discriminated current-evidence model with explicit assertion aspects: command plan, semantic path, source, selection, visible-line roles, physical geometry, repeat, undo, and view mode.
- Added all 20 previously missing named FishMark probe mappings. The shared catalog now contains all 33 named probes, and the executable probe registry fails fast if its IDs/groups drift.
- Kept all 70 exact command/container-path pairs queryable while representing their current execution state as an explicit full coverage gap.
- Reworked generated Enter behavior so Paragraph leaves owned by Lists split into sibling list items on required paths 2, 3, 6, and 9.
- Replaced raw-space depth inference with prefix-context analysis. Ordinary three- or six-space top-level text remains depth 0; list continuation indentation is recognized only when a preceding list prefix establishes it.
- Added `semanticDepth`, `contentColumn`, physical `markerColumn`, role, and active-aware visibility per physical line. Inactive structural separators are collapsed in WYSIWYM and remain visible in source mode.
- Removed inferred repeat/undo defaults. Every case supplies explicit operation counts and results, and runtime validation rejects missing/invalid counts, out-of-bounds selections, incomplete evidence, or incomplete physical-line records.
- Replaced unsupported full observed results for current defects with the exact observation proven by tests: `no-transaction` for the planner limitation and the truncated semantic path for nested block math.
- Corrected the RF-001 progress/intake/test-case documentation and returned the next skill to task execution.
