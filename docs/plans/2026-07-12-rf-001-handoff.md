## Outcome

The RF-001 corpus is now a canonical, executable specification model. It does not claim that the product editor has executed every target, so RF-001 remains `IN_PROGRESS`.

All 121 cases contain a complete initial result and an ordered `primary -> repeat` timeline plus an explicit undo branch. Checkpoints carry executable discriminated actions (`press-key`, `insert-text`, `set-selection`, `undo`) and explicit ancestry; there are no operation-count-only expectations, compatibility fields, or case-ID action inference.

Evidence is recorded as one mutually exclusive `Gap | Verified` value for every checkpoint/aspect target. Every typed observation and persisted provenance owns an exact case/checkpoint/aspect identity; `replaceEvidenceGaps` rejects cross-case reuse before comparing the observation with that checkpoint's canonical expected result, then atomically replaces gaps and recomputes case status. Metadata-only scenario execution is declared as capability metadata rather than recognized by scenario ID.

No product editor command, parser, CodeMirror adapter, IPC, editor test driver, or runtime editing behavior changed in this slice.

## What Changed

- Moved the complete implementation to `fixtures/editor-behavior`; the test harness and renderer import this root-owned corpus directly. The former package implementation and root compatibility re-exports were deleted.
- Added complete initial/primary/repeat/undo results, checkpoint ancestry, and executable action sequences to every case. Each result owns its actual semantic path, including structural exit/outdent checkpoints. The compound whitespace/Enter/text case explicitly records both `Enter` and `insert-text("abc")`.
- Removed `viewModeContract`; each result records its actual `viewMode`.
- Replaced overlapping evidence arrays with `Record<checkpoint, Record<aspect, Gap | Verified>>`. Empty reasons, empty provenance, duplicate target declarations, incomplete matrices, and partial failed updates are rejected.
- Added case-bound typed observation/provenance builders and atomic evidence replacement for a later runner. A target becomes verified only when observation case, provenance case/checkpoint/aspect, and canonical expected value all match through structural equality; non-finite numeric payloads and same-value results from another case are rejected. Dynamic replacement accepts repository-test provenance only; catalog-owned FishMark provenance is created and narrowed statically, so undeclared probe capabilities cannot be forged at runtime.
- Audited all 33 named probes from their executable `pass` conditions. The catalog owns conservative checkpoint/aspect capabilities and exact probe function provenance; the renderer registry validates each actual `run.name` against the catalog at module initialization, so swapped implementations fail fast. Verified probe evidence must match its exact catalog target and assertion. An empty capability list is valid metadata and never creates empty verified evidence.
- Removed geometry overclaims from code-fence, deep ordered-list, raw-prefix, table, and other partial DOM probes. No named probe currently claims semantic path, physical geometry, view mode, command plan, or undo.
- Added exact source text to every physical-line record and strict validation for line order, nonnegative depth/columns, source bounds, marker/content relationship, and source-line consistency.
- Made fenced-code and block-math bodies opaque under an ordered outer-container signature that records container kinds and list continuation widths. Each body line consumes only a CommonMark-equivalent continuation of that signature; leaving the container terminates the opaque block and reprocesses the line as ordinary Markdown. Code/math delimiters stay opaque across languages, and closing delimiters are recognized only after the complete outer prefix with 0–3 relative spaces.
- Removed all fixture type/data/helper re-exports from the test-harness public barrel and matrix scenario module. `fixtures/editor-behavior` is the only public fixture entry. The generic model no longer imports the concrete FishMark catalog; manifest composition performs the exact catalog narrowing without a model/catalog dependency cycle.
- Added explicit scenario execution capability. The matrix is `metadata-only`; the existing fixture-picker limitation is declared on its step rather than hard-coded by scenario ID.
- Hard-cut the CLI TypeScript layout to repository-root ownership: `tsconfig.cli.json` compiles both the harness and root fixtures with `rootDir: "."`. The single CLI entry is now `dist-cli/packages/test-harness/src/cli/bin.js` in package scripts and main-process development wiring. The installer continues to exclude `dist-cli` by design.
