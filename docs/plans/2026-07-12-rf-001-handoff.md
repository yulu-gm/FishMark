## Outcome

RF-001 now provides one typed, queryable editing-behavior baseline for the recursive Markdown structures required by the editor-foundation roadmap. It records desired behavior separately from known defects and does not change parser, command, CodeMirror, IPC, IME, undo-history, or product runtime behavior.

The only existing probe correction is a one-line expected-source update for leaving the last table row. The current table command contract deliberately inserts both a structural blank line and a new editable line (`\n\n`); the old probe expected only one newline. The same two stale assertions failed on the untouched plan-base commit, while the focused table command and renderer tests already assert the double-newline contract. No product behavior was changed.

## What Changed

- Added a typed behavior corpus with explicit initial and expected Markdown, source selections, per-physical-line semantic geometry, repeated-operation result, undo result, view-mode metadata, and evidence.
- Added all 70 required command/container-path pairs: seven commands across ten recursive parity paths.
- Added representative mixed-container cases at semantic depths 0 through 8.
- Classified every case as `desired` or `known-defect`; current observations never replace the desired contract.
- Added exact command/path filtering and exactly one registered `editor-behavior-matrix` scenario.
- Added a headless-runner guard so metadata-only steps cannot be reported as unexecuted passes.
- Added focused completeness, classification, geometry, filtering, registration, and deterministic-scenario tests.
- Added exact current-defect evidence for list/blockquote/list indentation and mixed-container block-path truncation.
- Added stable TC-017D documentation and the RF-001 intake/progress/handoff records.
- Included the behavior fixture in renderer and Vitest TypeScript project roots so the complete project gate typechecks it.

Temporary watchdog and structured-progress diagnostics used while isolating the old table assertions were removed in full. No diagnostic infrastructure, timeout policy, compatibility layer, or dead code from that investigation remains.

## Diagnostic Disposition

The initial unfiltered probe appeared stalled because its strict-human cases run slowly and provide no intermediate output. Instrumented investigation completed all 79 cases and isolated two deterministic table-exit expectation failures. Running the untouched plan-base commit reproduced exactly those failures, proving they predated RF-001. Existing table command and renderer tests establish `\n\n` as intentional behavior, so RF-001 corrects the stale probe fixture rather than the product.

All investigation-only watchdog/progress code and tests were reverted. The retained diff contains only the behavior baseline, its tests/docs/configuration, and the one stale assertion correction.

## Remaining Risks and Follow-up

- The current Electron editor-test driver cannot execute semantic geometry, undo/redo, or view-mode assertions. RF-001 records those contracts without claiming runtime execution; later parser/editor-model/adapter tasks must make them executable through the single canonical runner.
- Recursive List/ListItem paths are truncated by the current block-path adapter because it descends only blockquotes. Affected cases are labeled `known-defect`; RF-001 intentionally does not fix them.
- Mixed-container contracts without an existing named runtime probe remain `contract-only` until their owning later milestone.
- No macOS runtime execution was performed; the stored contracts use platform-neutral source offsets and semantic geometry.
