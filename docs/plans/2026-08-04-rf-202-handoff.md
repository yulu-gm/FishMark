## What changed

- Added structured-clone-safe shared apply/flush DTOs, closed error codes, staged wire decoders, and metadata-only projection events in `src/shared/document-edit.ts` and `src/shared/document-projection.ts`.
- Added `revision` and `savedRevision` to initial and legacy workspace document snapshots and every affected mapper/fixture.
- Extended workspace domain with strict client/base/change validation ordering, owner-aware atomic edit application, metadata-only normal results, conflict-only canonical text, and independent per-client high-watermark checkpoints.
- Renamed the deferred full-text application use case to `updateDocumentDraft`; added serialized `applyDocumentEdits` and `flushDocumentEdits` use cases using the same per-tab coordinator. Flush is a real `throughSequence` barrier, including zero and exact gap results.
- Replaced the inline preload product object with one complete `createProductApi` builder using only invoke/on/off/file-path/runtime ports. `preload.ts` now owns Electron composition, exposure, and the separate test bridge only.
- Added `src/main/ipc/register-workspace-handlers.ts`, which registers only RF-202 apply/flush, derives ownership from the live sender, keeps domain CAS inside the queue, publishes one owner-only projection for `applied`, never replays it for `duplicate`, and maps unexpected errors without stack leakage.
- Retained `UPDATE_WORKSPACE_TAB_DRAFT_CHANNEL` and its renderer bridge through RF-204, routed through the explicitly renamed `workspaceApplication.updateDocumentDraft` path.
- Extended architecture boundaries, dev emitted-JS wait lists, domain/application runtime verifiers, and focused cross-layer tests.

## Known risks and explicitly deferred work

- RF-203 still owns renderer client identity, animation-frame batching, pending queues, conflict rebase/recovery, and client lifecycle retirement. The new bridge is intentionally not the active renderer edit path yet.
- RF-204 still owns deletion of the full-draft channel and snapshot-preservation debt. RF-202 keeps exactly one explicitly named legacy path and introduces no feature flag or second document owner.
- RF-202 projection events acknowledge revisioned applied batches only; they do not claim that every legacy mutation already participates in a universal push store.
- Shared owns the closed wire error-message map used by main; domain/application retain runtime-neutral diagnostic messages. Combining them would create a forbidden domain-to-shared reverse dependency, so the two message surfaces remain deliberately separate while error codes stay aligned at the adapter boundary.
- The existing 8 lint warnings and Vite large-chunk advisory are unchanged. No performance budget is claimed by RF-202.
