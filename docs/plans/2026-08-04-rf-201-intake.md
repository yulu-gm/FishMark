# RF-201 Intake — Persistent Text Buffer and Session Revisions

**Task:** `RF-201 — Persistent text buffer and session revisions`

**Date:** 2026-08-04

**Status:** `COMPLETE` — formal acceptance `PASS` on 2026-08-04; see `reports/task-summaries/RF-201.md`

## Goal

Make every production main-process document session store canonical Markdown in a persistent CodeMirror `Text` value behind the runtime-neutral domain `TextBuffer` interface. Add a revisioned, idempotent document-edit batch primitive without exposing CodeMirror types or changing the current renderer/full-draft IPC contract before RF-202 through RF-204.

## In scope

- Add production package `@fishmark/workspace-infrastructure` with one public entry and a CodeMirror `Text`-backed `TextBuffer` implementation.
- Keep `@fishmark/workspace-domain` free of CodeMirror imports and accept a `TextBufferFactory` at workspace/session construction.
- Make main explicitly construct `WorkspaceState` with the infrastructure factory; no production string-buffer fallback path may remain in main composition.
- Validate edit positions as finite safe integers, sorted, non-overlapping, and in range against the original revision.
- Add a document-session edit-batch primitive with `baseRevision`, `clientId`, `clientSequence`, and `TextChange[]`.
- Advance the document revision exactly once for every non-empty accepted batch, including a same-text replacement; preserve it for duplicates, conflicts, gaps, invalid input, and rejected empty batches.
- Track a per-client contiguous acknowledged sequence high-watermark. Sequence starts at 1; `<= high-watermark` is an idempotent retry, `high-watermark + 1` is admissible, and a larger value is a typed `sequence-gap`.
- Activate workspace-infrastructure architecture/public-entry guards, build/watch/clean/typecheck wiring, dependency classification, and an emitted runtime verifier.
- Cover Unicode/UTF-16 offsets, emoji, CRLF preservation, multiple changes, large documents/insertions, invalid ranges, stale revisions, sequence gaps, and duplicate retries.

## Out of scope

- Shared/preload IPC edit DTOs or a main edit handler (`RF-202`).
- Renderer pending queues, conflict rebasing, or editor client lifecycle (`RF-203`).
- Removing full-draft update IPC and old renderer draft synchronization (`RF-204`).
- Parser caches, recursive Markdown structure, semantic commands, or visible editing behavior changes.
- Timing budgets or a parser worker; measured performance acceptance remains RF-901.
- A compatibility facade, global mutable text-buffer factory, dual canonical session, or CodeMirror type leakage into domain/application contracts.

## Design choice

Three approaches were considered:

1. **Inject a domain `TextBufferFactory`; implement it in workspace-infrastructure — selected.** This keeps one canonical main-owned session, permits persistent structural sharing, and preserves dependency direction.
2. Import `@codemirror/state` directly into workspace-domain — rejected because it violates the domain boundary and leaks infrastructure into business types.
3. Keep string-backed domain state and add a parallel main-side CodeMirror cache — rejected because it creates dual document truth and invalidation complexity.

The existing `StringTextBuffer` remains a domain conformance/reference implementation for isolated domain tests. `createWorkspaceState` requires an explicit factory: tests pass `createStringTextBuffer`, while production main passes `createCodeMirrorTextBuffer`. There is no default, runtime feature flag, or compatibility branch selecting between representations.

## Acceptance

- Production main sessions use CodeMirror `Text` through `TextBuffer`; domain/application public types contain no CodeMirror type.
- Small edits use the persistent buffer API and do not rebuild the whole source string inside the infrastructure implementation.
- Edit batches are validated against original-buffer offsets and applied atomically.
- One accepted non-empty batch increments revision exactly once, including a same-text replacement; an empty batch is invalid and does not acknowledge the sequence.
- Duplicate sequences never reapply edits; stale base revisions and sequence gaps are distinct typed results.
- Unicode, emoji, CRLF, multi-edit, large insertion, invalid-range, duplicate, stale, and gap tests pass.
- Workspace-infrastructure has one public entry, emitted runtime resolution, a fail-closed dependency guard, and no Electron/React/main/preload/renderer/shared dependency.
- Current open/edit/save/reload/close behavior and RF-101/RF-102 ownership/lease invariants remain unchanged.

## Risks

- CodeMirror `Text` uses UTF-16 offsets and logical line separators; construction must preserve literal CR characters so CRLF round-trips exactly.
- Applying multiple changes sequentially from the front would shift later coordinates; implementation must apply against the original document, either with CodeMirror changes or reverse-order replacements.
- A per-edit Set would grow with every keystroke; the contiguous per-client high-watermark is required.
- Treating a sequence gap as a duplicate could silently lose input; it must fail with `sequence-gap`.
- Leaving main on the default string buffer would make the package cosmetic and fail RF-201.
