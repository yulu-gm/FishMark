## 改了什么

新增 `@fishmark/codemirror-adapter`（沿用 `editor-model` 的源码别名包形态，无独立 package.json/tsconfig）：

- `transaction-adapter.ts`：CodeMirror 事务 ↔ 语义 plan 的转换层。持有每个 view 的 `DocumentStructureCache` state field（单范围走增量缓存、其他重解析、revision 每次变更 +1 严格单调）；`prepareCommand`/`preparePlan` 在派发前拒绝 stale 或跨 session 的 plan；`recordEditorDispatch` 用「事务将产生的 cache revision + 文档文本」双重校验，只为自己算出的文本入队；组合输入期间冻结结构决策；`rebindSession`/`releaseSession` 管理绑定与 generation。
- `selection-mapper.ts`：纯选择映射。`SelectionMapper` 以 (snapshot, selection) 为键复用上下文，光标移动不重建文档派生快照；`checkPlanRevision` 区分 stale（revision 不匹配）与 foreign-session（generation 不匹配）。
- `composition-controller.ts`：纯状态 IME 控制。组合期间冻结几何刷新、结束后按最终文本请求**恰好一次**重算并给出 `CompositionFinishReceipt`（含显式原因）。
- `candidate-performance.ts`：候选路径性能探针，直接跑 adapter 使用的同一组缓存操作，报告每个编辑的 `fullParseCount`、`parsedSourceLength`、`fallbackReason` 与耗时。
- `index.ts`：包公共入口。

历史分组（`historyAnnotationFor`）：`navigation` → `select`（不产生 history 事件）；`structural` → `isolateHistory.of("before")`，让自动补全成为独立可撤销步骤；普通文本输入映射到 CodeMirror 原生 `input.type`，从而保留连续键入合并为一次撤销的能力。**实现期修正**：最初把所有命令都写成 `input.<commandId>`，实测导致连续键入被拆成多次撤销，故 `insert-text` 特判为 `input.type`。

边界与配置：

- `packages/editor-core/src/commands/editor-model-bridge.ts` 及其测试**删除**，桥接职责整体迁入 adapter。原因：guard 禁止 `packages/editor-core` 之外的包直接 import `@codemirror/*`，而 adapter 必须持有 state field；若保留旧文件只能留下两份重复实现。这移除了 roadmap 中「`retireIn: RF-604`」的 bridge 特例，也落实了 roadmap 的最终目标「bridge 归 `@fishmark/codemirror-adapter`」；RF-604 仍需完成 `code-editor.ts` 的工厂切换。
- `fixtures/architecture/editor-foundation-guard.json`：`codemirror-adapter` 由 `planned` 激活为 `active`，新增 `boundary.codemirror-adapter`（禁止 react/react-dom/electron/node:* 与 `src/main`、`src/preload`、`src/shared`、`src/renderer`、三个 workspace 包），并删除 3 条已失效的 editor-core bridge 例外。
- 别名：`tsconfig.base.json`、`tsconfig.renderer.json`、`tsconfig.vitest.json`、`vite.config.ts`、`vitest.config.ts` 增加 `@fishmark/codemirror-adapter`。

队列接入：adapter 只依赖窄端口 `EditorChangeFramePort.admitFrame`，真实集成由 `src/renderer/editor/codemirror-adapter-queue-integration.test.ts` 用真实 `WorkspaceEditClient` 验证；**没有第二套队列、序列或传输状态**。adapter 只报告而不拥有版本：`localRevision` 来自自身缓存，`acknowledgedRevision` 来自队列已确认，`observedRevision` 来自投影观测到的 canonical revision（三者语义不同）。

## 已知风险与未做项

- **未切换生产入口**：`src/renderer/code-editor.ts` 仍走旧语义引擎，本轮 adapter 没有生产消费者。`npm run test:editor-behavior`（121/121 正式 Electron 语料）不构成本轮证据，切换入口时（RF-506）必须重跑。
- 真实平台 IME、跨 IME 的光标/组合行为未被本轮证明；本轮只证明 adapter 级组合状态机与 JS 事件序列。
- 20k 探针只测缓存/桥接路径，**不是**按键到绘制、掉帧或内存预算；那些属 RF-901/902。
- 20k 零 full-parse 用例耗时较高（本机数秒），已加长超时预算；快路径的候选筛选目前对根级段落做的是 O(children) 扫描，是否优化留待后续性能任务评估。
- 掉电安全、fsync 等仍不属本轮（沿用 RF-HARDEN-001 的明确限制）。
- 未跑 `perf:baseline`：本轮未改 canonical baseline 契约或 bundle 组成（adapter 尚未被 renderer 引用，无 bundle 影响）。切换入口时必须跑。
