## 已实现的职责边界

- 将既有 `WorkspaceRendererApplication`、`WorkspaceMutationCoordinator`、`editor-shell-state` 与 `editor-load-identity` 从 `renderer/editor` 迁到 `renderer/application`，删除旧路径；复用原 `WorkspaceEditClient` / `PendingEditQueue`，没有第二份 Markdown 真值、transport 队列或兼容 facade。
- application 继续持有成熟 canonical projection、edit bindings、close lease、recovery 与 coordinator。增加稳定的 optimistic view cache；后续 frame 即使 dirty 不变，也通过原 store 发布派生视图更新。`getState` 和 `getEditorViewSnapshot` 在未变化时保持引用。
- application.commands 收口 open/save/save-as/autosave/reload/close/reorder/move/detach、recent、drop、export 与通知。跨窗口 move 使用与 close/detach 相同的 sealing、drain、canonical reconciliation 和 release；主进程协议不变。
- `WorkspaceSaveScheduler` 只持有 timer/replay/origin；文档读写仍进入 application 原事务。销毁清理 timer 并阻止晚到通知/replay；reset 不把真实 in-flight save 误报为空闲。test driver 保存与菜单/按钮保存共享同一 manual policy，包括 external conflict 的 save-as。
- 外部冲突 resolve 进入 application coordinator/barrier，不由 React 直接调业务 IPC；reload 继续经过编辑器 sealing/release。notifications 与错误映射在非 React owner，React 仅负责展示。
- `RendererPlatformGateway` 私有持有受限业务 bridge，负责 recent 错误通知、clipboard/link 结果映射、settings 操作错误消息、图片目录选择到 preferences 更新、preferences 更新后的自动保存调度。纯事件、平台 getter、只读 bootstrap 与 DOM file 转换仍在 composition。
- 保留薄 `useWorkspaceController` / `useEditorApplicationController`，只做实例、presentation 注入、订阅与生命周期绑定；删除 `useSaveController` / `useEditorWorkflowController` / `useExternalConflictResolution`。frame、discard、remote-patch 契约从 CodeMirror 实现迁到 `application/editor-port.ts`，application 不反向依赖 React/editor 目录。
