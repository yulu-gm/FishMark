# Editor scrollbar candidate — 2026-10-20

Base: released 4.0.0, `06b6372d18b47f34dd00dd0287d562386b3aee2f`. Local candidate only; no commit, push, tag or release.

The requested behavior is continued dragging when the pointer deviates horizontally, rather than Chromium's platform snap-back. No supported per-element Electron/Chromium toggle was found. The candidate adds one renderer-local CodeMirror view plugin with two small scrollbar controls over the existing document scroll container. It does not replace the editor, height map, wheel handling in the content, Markdown text or history. Nested widget scroll areas keep their existing behavior.

Native document scrollbars are hidden through a persistent `EditorView.editorAttributes` class. Thumb pointer capture owns its drag; the perpendicular pointer coordinate does not cancel it. Track presses page immediately, then repeat after a 350 ms delay at 60 ms intervals while held. Leaving the track pauses without polling; reentry resumes, and the thumb stops at the pointer. Release, cancellation, capture loss, blur, explicit navigation and teardown clear the timer. Each control exposes scrollbar role, orientation, current/max value, controlled scroller ID and keyboard access. Keyboard Home/End address document endpoints and remain at the requested edge while measurements settle, until new input or navigation cancels that intent. Pointer movement, release, cancellation, capture loss, resize and teardown have explicit handling. Track wheel events forward deltas; ordinary wheel and editor keyboard input retain the scroll container and editor handlers. Touch action is restricted only on the controls.

The 4.0.0 native-drag ratio plugin and its obsolete tests are removed from this candidate. The Markdown host policy still prevents scrollbar pointer events from moving document selection. Geometry reads use `requestMeasure`, queued after the editor's own measurement loop, with one post-measure microtask for active control intent. There is no polling loop, native drag cancellation, Chromium binary patch, security setting change or alternating native/custom scroll authority.

Final evidence is in the primary checkout's ignored `.artifacts/scrollbar-repeat-20261020/` directory. `browser-10.json` records 36 pointer cases plus 18 controls on an Electron 41.2.0 / Chromium 146.0.7680.179 offscreen window. `browser-11.json` adds 9 controls for actual host/window resizing, horizontal dragging and wheel input, normal editor navigation, and edit/undo. All 63 checks pass with no page errors or console warnings. The 36 drag cases preserve source, focus and selection; maximum measured thumb-center error is 0.006142 CSS px and release displacement is zero. Screenshots, pointer coordinates, actual thumb bounds, scroll position, total height and viewport ranges are retained separately; this is not a claim of desktop visual acceptance.

Remaining validation: real Windows pointer capture across an actual window boundary, physical touchpad input, screen-reader behavior, high DPI and macOS. Offscreen pointer coordinates outside the viewport do not prove OS-level capture across windows. Nested native scrollbars retain Chromium's own snap-back. Real desktop validation would need roughly 2–3 minutes in a new temporary test window; it has not been started or authorized by this candidate report.

Earlier failures and partial attempts are retained, including a sandbox cache rename failure, a Vite import preparation failure, default-port collision, and intermediate type/lifecycle/End and measurement-loop defects. Final assertions are not inferred from reversed `scrollTop` alone. Repository regression allowlists are unchanged. Version metadata remains 4.0.0.
