## Bundle provenance and Source Map model

`scripts/vite-bundle-provenance.ts` uses a two-phase Vite plugin:

1. `generateBundle` records the exact chunk graph, module IDs, imports/dynamic imports, entry flags and whether Rolldown emitted a map.
2. `writeBundle` reads final on-disk code/map bytes, verifies the generated expectation in both directions, computes SHA-256 values and atomically writes provenance.

The schema uses `hasSourceMap: boolean`, `mapFileName: string | null` and `mapSha256: string | null`:

- `hasSourceMap: true` requires the final map and a matching map hash;
- `hasSourceMap: false` requires both map fields and the final disk map to be absent;
- attested mapless chunks are reported as `sourceMapEvidence.status: NOT_EMITTED`, never `COMPLETE`;
- mapless chunks retain full forbidden-source authority through provenance `moduleIds`;
- emitted malformed maps remain `INCOMPLETE` and fail integrity checks;
- missing/duplicate/extra records, schema/field drift, payload/code/map hash mismatch, dependency mismatch or closure mismatch fail closed.

No virtual/real identity-map helper, generated-code whitelist, compatibility schema or analyzer exemption remains. `write:false` builds produce no filesystem provenance. Ordinary builds remove provenance and emit no `.js.map` files.
