## Implemented changes

### Slice A — architecture and parser-entry guard

- Added a versioned, non-empty manifest for active/planned packages, forbidden imports, public package entries, exact exceptions, parser entries, direct micromark document sites, lifecycle retirement tasks and bundle checks.
- Added fail-closed repository evidence collection for missing/non-directory roots, filesystem failures and TypeScript parse failures.
- Scans static imports, re-exports, string-literal dynamic imports, import type, TypeScript import-equals and literal `require`; shadowed literal `require` is conservative dependency evidence while comments, ordinary strings and non-literal calls do not match. Micromark document-site evidence follows ES/import-equals namespace aliases, literal require/dynamic-import namespace bindings, namespace aliases, namespace destructuring, extracted/renamed/aliased `parse` bindings, static `.parse` / `["parse"]` access and direct module-expression `.parse()` calls through awaited/parenthesized expressions. Findings use ordinal ordering.
- Rejects unregistered public/internal parser surfaces, aliases, namespace/default exports and direct micromark document parse sites.
- Active packages must bind one-to-one to their own active `forbidden-imports` rule with an identical normalized `sourcePath`; public-entry/wrong-path/reused rules cannot satisfy a package boundary.
- Keeps current CodeMirror ownership legal only through 73 scanner-equal, stale-checked `(ruleId, importer, specifier)` exact exceptions assigned to `RF-604`; the previous wildcard temporary allowance and all of its code paths were deleted.

### Slice B — committed fixture and honest current counters

- Added the single committed 20,000-line mixed-Markdown fixture with LF-only/no-final-newline identity and SHA-256 `545601ad9d770898e23e5551e938bcaa4ebaecd8446941a4145a4db8777f6d37`.
- Added stable open/edit/selection/ordered-list/outline/metrics report schema and operation-boundary counters.
- Preserves `parseMarkdownDocument` / `parseBlockMap` provenance; unavailable incremental cache counters remain zero with `incremental-structure-cache-not-implemented`.
- Runtime durations are finite/non-negative information only and are not committed CI thresholds.
- Outline and metrics accept optional parser injection for measurement while preserving their default production behavior.

### Slice C — emitted bundle evidence and unified gate

- Extended the existing analyzer JSON with top-level `schemaVersion: 1` and `bundleEvidence.evidenceScope: emitted-renderer-output`.
- Moved the 4 maximum limits, 4 required lazy patterns and 15 forbidden initial source groups out of `package.json` into the architecture manifest. `perf:bundle` passes only `--contract`, dist and display parameters; no public baseline policy is duplicated in CLI flags or analyzer code.
- Contract mode validates non-empty versioned policy data, exact kind fields, canonical IDs, supported metrics, positive integer limits and duplicate IDs/semantic targets; it cannot be mixed with ad-hoc policy flags. JSON evidence includes contract path, both schema versions and SHA-256.
- Evidence includes ordinally sorted initial static-import closure, lazy requirements, initial source groups, source-map completeness, stable applied check IDs, actual values, limits and `PASS/FAIL`.
- Normalizes duplicate lazy/source-group CLI rules and uses deterministic tie-breaks for every emitted array.
- Forbidden initial source-group rules inspect every initial chunk. Missing maps, invalid JSON, missing/wrong Source Map v3 `version`, missing/non-array/invalid `names`, missing/non-string/empty/invalid/unmapped `mappings`, out-of-range source/name references, invalid `sources` / `sourcesContent`, mismatched counts and missing corresponding content produce machine-readable incomplete evidence, `FAIL`, and exit code 1. The analyzer parses every Base64-VLQ segment itself and does not rely on an undeclared transitive package.
- Source import graph authority remains the Slice A guard; the analyzer explicitly reports emitted output and does not claim to be a TypeScript dependency graph.
- A sourcemap-build-only Vite plugin emits identity maps for chunks whose module IDs are all NUL-prefixed Vite/Rolldown virtual runtime modules and which otherwise have no map. Each non-empty emitted line maps to source index 0 and the corresponding original line in one synthetic source; `sourcesContent[0]` is the exact emitted code and sorted module IDs live only in `x_fishmark_virtual_module_ids`. This is not an analyzer exemption: mixed/non-virtual/source-bearing chunks remain untouched and therefore fail the strict analyzer if their map is absent.
- Added `test:editor-foundation`; `perf:baseline` now runs bundle evidence and the same architecture/fixture/report/analyzer tests.
- Updated the decision log, stable regression cases and current package/parser boundary READMEs.
